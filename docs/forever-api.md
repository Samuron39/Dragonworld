# WoW Forever: API notes

Things learned while building Dragonworld that are easy to get wrong. The game is **WoW Forever**, not retail or classic.

## Client

- Addons go in `World of Warcraft\_forever_\Interface\AddOns` (product `wowf`, 1.60.1). On the main development PC the game is in `D:\wow\World of Warcraft\_forever_`.
- TOC: `## Interface: 16001`. `WOW_PROJECT_ID` is 18 (`WOW_PROJECT_CAMELOT`).
- The API is the modern (Midnight-style) one, with secret values active: `TooltipDataProcessor`, `C_Container`, `C_QuestLog`, `C_Item`, `MenuUtil`. The old global `GetItemInfo` does not exist; use `C_Item.GetItemInfo`.
- `/reload` picks up Lua changes; a new file in the .toc or a new texture needs a full game restart.

## Where to check an API

- Blizzard's own UI code for Forever is mirrored at GitHub `Gethe/wow-ui-source`, branch `forever` (Forever-specific overrides in `Camelot/` subfolders; generated API docs in `Blizzard_APIDocumentationGenerated`, incomplete). Read a file with `gh api "repos/Gethe/wow-ui-source/contents/<path>?ref=forever" -H "Accept: application/vnd.github.raw"`; list files with `git/trees/forever?recursive=1`.
- The Warcraft Wiki API pages list a "forever" row per function.
- Other addons installed in the game's AddOns folder run on the live client, so grepping them confirms that a call or template exists.

## Facts

- **Names:** characters have first and last names ("Akro Polis") and there are no realms. The same name may be reported with or without the space, or as "Akro-Polis". Match people by GUID (17th value of `GetGuildRosterInfo`, `UnitGUID("player")`), or use `DW.IdentityKey` / `DW.SameCharacter` (Core.lua, Admin.lua). `DW.NameKey` keeps only the part before the first `-` and must not be used for identity.
- **`ReloadUI()` is protected:** called from addon code, even from a click, it fails with "Interface action failed because of an AddOn". Reload through a `SecureActionButtonTemplate` button with `type = "macro"`, `macrotext = "/reload"`, registered for up and down clicks (see Update.lua). Secure frames cannot be shown, hidden, moved or changed in combat; `PLAYER_REGEN_DISABLED` fires just before the lockdown.
- **Hardware events:** `DeleteCursorItem()` (one item per click), `C_Calendar.AddEvent()` (call from a click, never a timer; it returns nothing, and a refusal comes later as `CALENDAR_UPDATE_ERROR`), calendar invites (one character per click), `C_TradeSkillUI.OpenTradeSkill(skillLineID)` (one per click; the skill line is the 7th value of `GetProfessionInfo(index)`), `InviteUnit` and `ConvertToRaid`. `SetBinding` is blocked in combat.
- **Spec** means the two talent groups: `C_SpecializationInfo.GetActiveSpecGroup()`, `GetNumSpecGroups()`, event `ACTIVE_TALENT_GROUP_CHANGED`.
- **Talents:** the old functions (`GetNumTalentTabs`, `GetTalentTabInfo`, `GetTalentInfo`) do not exist. The talent window is a trait tree: `C_ClassTalents.GetActiveConfigID()` (or `C_SpecializationInfo.GetCombatConfigIDForSpecGroup`), `C_Traits.GetConfigInfo(config).treeIDs[1]`, `GetGroupDisplayInfoByTreeID`, `GetTreeNodes`, `GetNodeInfo` (ranksPurchased/activeRank, groupIDs), entry -> definition -> spellID. `ForeverDungeonJournal\Systems\CharacterSnapshot.lua` is a working reference.
- **Bank:** containers 6-14 (`Enum.BagIndex.CharacterBankTab_N`), keyring -1. Read the bank only between `BANKFRAME_OPENED` and `BANKFRAME_CLOSED`.
- **Guild bank:** `GetGuildBankItemInfo`, `GetGuildBankItemLink`, `GetGuildBankTabInfo`, `GetGuildBankMoney`, events `GUILDBANKBAGSLOTS_CHANGED` (no payload) and `PLAYER_INTERACTION_MANAGER_FRAME_SHOW` (GuildBanker = 10) exist. `QueryGuildBankTab`, `GetNumGuildBankTabs`, `GetCurrentGuildBankTab` are unconfirmed (`/dw debug` shows whether they exist). A tab not yet received reads exactly like an empty tab.
- **Guild:** `GetGuildInfo("player")` can be nil right after login. The guild message of the day: `C_GuildInfo.GetMOTD` first.
- **EditBox:** `SetMaxBytes(n)` lets only n - 1 bytes in. Use `SetMaxLetters(n)` for an exact character count.
- **Professions:** confirmed in game: `C_TradeSkillUI.GetAllRecipeIDs`, `GetRecipeInfo(id).learned`, `GetRecipeSchematic` while your own profession window is open. `C_TradeSkillUI.GetTradeSkillListLink()` gives `|Htrade:<playerGUID>:<spellID>:<skillLineID>|h[Name]|h`, but opening another player's profession link did nothing between two guildmates. `GetBaseProfessionInfo()` also describes a linked profession: check `IsTradeSkillLinked()`. The professions frame shows only professions where `C_TradeSkillUI.CanTradeSkillShowCraftingUI(spellID)` is true, so gathering professions have no recipe window.
- **Legacy points** (account-wide, "Legacy Points 2 / 65"): no documented API; third-party addons read them as `C_MajorFactions.GetCurrentRenownLevel(2802)`, max `C_Traits.GetMaxAvailableTraitCurrency(4225, false)`. `GetTotalAchievementPoints()` is not it. Not confirmed in Dragonworld.

## Read from Blizzard's source and other addons (not yet tried in Dragonworld)

Found while planning the Tactics tab (November 2026, build 1.60.1.71091). "Live" means an addon that runs on the Forever client does it; the rest is from Blizzard's Forever UI source only. Move a line up to Facts once it is confirmed in the game.

- **Group and raid:** `MAX_RAID_MEMBERS = 40`, 8 groups of 5; the client names 5, 10, 20 and 40-player sizes. `GetRaidRosterInfo(i)` gives name, rank (2 leader, 1 assistant), subgroup, level, class, fileName (the class token), zone, online, isDead, role, isML, assignedRole. `UnitIsGroupLeader`, `UnitIsGroupAssistant` and `UnitGroupRolesAssigned` are secret only for units outside your party or raid. Roles can be assigned (`UnitSetRole`, the role button in the unit menus). `GetRaidTargetIndex` returns secrets and `SetRaidTarget` is restricted: use the raid target icons as art only.
- **Addon messages:** chat types seen live: GUILD, PARTY, RAID, INSTANCE_CHAT, WHISPER. No chat type reaches a community (club stream); `C_Club.SendMessage` posts visible chat. `Enum.SendAddonMessageResult`: 0 success, 3 throttled, 5 not in group, 8 channel throttle, 10 not in guild, 11 `AddOnMessageLockdown`.
- **Addon restrictions:** `Enum.AddOnRestrictionType` = Combat, Encounter, ChallengeMode, PvPMatch, Map, Chat; `C_RestrictedActions.GetAddOnRestrictionState(type)`, event `ADDON_RESTRICTION_STATE_CHANGED`, `C_ChatInfo.InChatMessagingLockdown()`. Blizzard's text: values become secret "when encounter, challenge mode, or PvP match addon restrictions are in effect, and when the player is on a communication-restricted map such as a dungeon or raid". So sending is blocked during a boss fight in an instance. Whether it is also blocked while merely standing inside the instance is not known: test it. Inside dungeons the combat log already hides GUIDs (live, DungeonJournal).
- **Encounter journal:** Blizzard's journal window is not loaded on Forever (`Blizzard_EncounterJournal.toc`: `AllowLoadGameType: standard, classic`), and the world map has no boss pins. The functions exist and are used live inside `pcall`: `EJ_GetNumTiers`, `EJ_SelectTier`, `EJ_GetInstanceByIndex(i, isRaid)`, `EJ_SelectInstance`, `EJ_GetEncounterInfoByIndex`, `EJ_GetCreatureInfo` (select the tier and the instance first; Forever's new dungeons are in a tier of their own). No addon has raid data yet.
- **Dungeon maps:** `C_Map.GetMapArtLayers(uiMapID)[1]` (layerWidth, layerHeight, tileWidth, tileHeight) and `C_Map.GetMapArtLayerTextures(uiMapID, 1)` work (live: RareScanner, DungeonJournal). Classic dungeon floors are 1002x668 in 256x256 tiles, 4 across and 3 down, listed row by row from the top left. Forever's own new dungeons (Hall of Thanes, Ruins of Lordaeron, ...) have no map art in the client. Map ids can change between builds: check that art exists, or find the map by name over `C_Map.GetMapInfo(1..3000)`.
- **Creature portraits:** `SetPortraitTextureFromCreatureDisplayID` uses a render target per portrait; DungeonJournal crashed the graphics device with hundreds and now keeps at most 48 alive. A portrait is a black square until the model has loaded.
- **Drawing:** `frame:CreateLine()` with `SetStartPoint("TOPLEFT", parent, x, y)`, `SetEndPoint`, `SetThickness`, `SetColorTexture`; `Texture:SetRotation`; `CreateMaskTexture` / `AddMaskTexture`. Short line segments leave notches where they meet (DungeonJournal puts a disc on each joint).
- **Guild & Communities window:** `CommunitiesFrame` is 814x426; a guild page (`GuildBenefitsFrame`, `GuildDetailsFrame`) is 608x333, starting 194 right and 63 down. Its side tabs are `RightSideTabTemplate` (32x32, 20 apart); five of Blizzard's plus two of ours reach the bottom of the window. Nothing in it is secure, but it is a UI panel: `ShowUIPanel` refuses addon callers in combat. Do not call `SetDisplayMode` or write keys on the frame: that taints the path to `C_GuildInfo.SetNote`, `SetMOTD` and `C_Club.SendMessage`.
- **The game's own windows:** there is no Achievements micro button; `ToggleAchievementFrame()` opens the Legacy window (`LegacySystemFrame`, 920x575) on Legacy Challenges. Professions is `ProfessionsFrame` (673x594), Dungeons is `LFGParentFrame` (458x535, `Blizzard_GroupFinder_VanillaStyle`, a secure addon). All are UI panels that re-anchor themselves to UIParent when shown, so they cannot be moved into another window.
- **Side tabs of those windows:** `LargeSideTabButtonTemplate` (`SidePanelTabButtonMixin`, `Blizzard_SharedXML`) has no size in XML: `OnLoad` sets it from the atlas `common-sidetab` (Forever's is wider than retail's; the art has empty space on its right). In all three windows the first tab's TOPLEFT sits on the window's TOPRIGHT, 60 down, the rest 2 apart, so the tabs stick out exactly one tab width; the guild window's `ChatTab` is the same, 36 down. `SetChecked(on)` shows `SelectedTexture`; `OnMouseUp` plays the tab sound itself and then calls the handler from `SetCustomOnMouseUpHandler(self, button, upInside)`. `OnHide` also runs when the whole interface is hidden (Alt+Z): `IsShown()` is still true then.
- **Click casting:** Forever ships `Blizzard_ClickBindingUI` and `C_ClickBindings`; `SecureUnitButton_OnClick` asks `C_ClickBindings.GetBindingType` first, and the window opens from Options > Keybindings (`ToggleClickBindingFrame()`). Blizzard's unit frames do not use the addon convention `ClickCastFrames` / `ClickCastHeader`. The addon Clique supports Forever since 5.1.0; its licence is all rights reserved, so its code must not be copied into this repository.
- **Guild identity:** `C_Club.GetGuildClubId()` (may be nil); a guild can be renamed (`Blizzard_GuildRename`), so the name is not a permanent key.
- **`UnitIsUnit`** is marked `SecretWhenUnitComparisonRestricted` in Blizzard's docs ("only applies on an addon-restricted map"), so inside a dungeon or raid `UnitIsUnit("raidN", "player")` may be secret. `DW.GroupUnits` leaves such units out; code that must see the whole raid there walks `raid1..N` itself and finds the player by name (TacticsCore.lua, `GroupUnitList`). Ask `DW.IsSecret(value)` before any `value == nil` or `not value`: a comparison or a truth test on a secret throws.
- **Instance groups:** a group made by the game's group finder is an "instance group": `IsInGroup(LE_PARTY_CATEGORY_INSTANCE)` is true and `IsInGroup(LE_PARTY_CATEGORY_HOME)` false, and addon messages go on `INSTANCE_CHAT` (Blizzard's chat edit box does the same test); RAID or PARTY would answer 5 there. Whether Forever's group finder makes such groups is not known.
- **Still to find out in the game (Tactics):** how the sender of a RAID / PARTY addon message is written (first and last name, or first name only); whether addon messages go out while you merely stand inside an instance, out of combat; whether any are lost over a loading screen. `/dw debug` shows the game's answers under `[tactics]`.
- **Menus (`MenuUtil.CreateContextMenu`):** a radio or check choice leaves the menu open unless its function returns `MenuResponse.Close` (Open 1, Refresh 2, Close 3, CloseAll 4). A long menu scrolls after `root:SetScrollMode(maxHeight)`. Used by the Tactics editor; not yet seen in the game.
- **Keyboard:** `Frame:SetPropagateKeyboardInput` has restrictions on Forever (it may be refused in combat), so a frame that takes keys with `EnableKeyboard` can swallow the player's keybinds in a fight. Dragonworld takes no keys outside text fields.
- **Timed items:** no function tells that an item has a time limit ("Duration: 4 min" in its tooltip; a quest item that must be delivered in time). The generated docs have `C_TooltipInfo.GetBagItem(bagIndex, slotIndex)`, which gives the tooltip as data (`lines[i].leftText`, read that way live by ForeverDungeonJournal with `GetItemByID`); Ryddesekk looks for a line that starts like the game's `ITEM_DURATION_DAYS` / `_HOURS` / `_MIN` / `_SEC` texts. Those global names are retail's and are not in the UI source: not yet confirmed in the game.
- **Sounds and fonts:** `SOUNDKIT` is loaded from `Blizzard_SharedXML\[Family]\SoundKitConstants.lua`, and the Forever branch has only the `Mainline` one (plus a Wrath one for other clients), so retail's names apply: `IG_QUEST_LOG_OPEN` 844 (a soft page sound, used when the Tactics slideshow opens by itself), `IG_MAINMENU_OPEN` 850, `MAP_PING` 3175, `RAID_WARNING` 8959, `READY_CHECK` 8960. The font objects are in `Blizzard_Fonts_Shared\Shared\FontStyles.xml`: besides the usual ones, `GameFontNormalHuge` / `GameFontHighlightHuge` (20) and `GameFontHighlightMedium` (14). The small red x `Interface\Buttons\UI-StopButton` is not named anywhere in Forever's UI source, so it may not exist: the slideshow's small button draws its x as text.

## Profession data (Wowhead)

Wowhead's Forever profession leveling guides load their data from two JSON endpoints that `curl`/Node `fetch` can read with a browser User-Agent:

- `https://www.wowhead.com/forever/profession-leveling-guides/catalog?skill=<skillLine>`: every recipe (spell, skill colours, reagents, created item, trainer/vendor/drop/quest source) plus items and vendors.
- `https://www.wowhead.com/forever/profession-leveling-guides/guides?skill=<skillLine>`: the leveling guides; the one with `official: true` is "Tried & Tested in Forever".

Skill lines with guides: 171 Alchemy, 164 Blacksmithing, 333 Enchanting, 202 Engineering, 165 Leatherworking, 197 Tailoring, 185 Cooking, 129 First Aid. `tools\make_profession_data.js` turns this into `Dragonworld\Modules\ProfessionData.lua`. Forever has its own items and recipes, so classic data is no substitute.
